# Edit and publish content

1. Open **Authoring studio**. The currently built catalog is the base revision.
2. Edit discovery descriptions, credits, prerequisites and methods through the forms. Legacy instructions and source notes stay separate from refined methods. Use **Media & tutorials** to add a source, select its role, and reorder references. A Tutorial becomes the preferred click-to-load player without deleting proofs.
3. Use **Save browser draft** for a device-local save, or **Export draft backup** for a portable JSON backup. Browser saves use only `mcd2speedrunning:draft:v1`; no other project's data is cleared. Undo/redo is kept for the current session. Navigating to a catalog preview keeps the studio draft mounted in this session.
4. **Preview catalog** opens the draft reader, including uploaded screenshot previews. Its banner says local draft; public content has not changed.
5. **Export changed files** validates the catalog and checks `content-revision.json` when reachable. A newer upstream revision blocks whole-file export. When the upstream check is unavailable the summary explicitly requires a revision comparison before committing. Stale imported drafts are rejected, with branch/PR reconciliation guidance.
6. Extract the ZIP. Copy only its `content/` and `public/` files to the matching paths in `A-Birdi/mcd2speedrunning`. Keep `_studio/draft.json` outside the public repository as a local backup. Read `CHANGE_SUMMARY.md` and review the diff. No component code edits are needed for descriptions, discoveries, media, subsection screenshots or route ordering.
7. Run `npm run check`. If you deliberately edited JSON outside Studio, run `npm run revision` first and include the updated meta.json; validation rejects a stale content revision. Commit reviewed changes through a local checkout/GitHub Desktop, or upload the files to their exact directories using GitHub's website. The initial migration comparison `npm run audit` is an optional historical review after cutover; ongoing corrections do not have to equal the original source wording.
8. Complete the outstanding one-time repository setting: **Settings → Pages → Build and deployment → Source → GitHub Actions**. Keep this source selected thereafter; it removes the competing raw-source branch build. Reviewed commits on main automatically run **Validate and publish GitHub Pages**: content/type/build checks, Chromium/Firefox/mobile browser checks, then compiled-dist deployment. Pull requests validate without publishing. A passing deployment and verified public URL establish Published status. A browser draft, exported ZIP, commit, or successful build alone does not.

Ordinary file import/export works without the File System Access API, including on Firefox. Browser storage can be unavailable or full; a draft backup is the recovery path. Draft schema version 1 is supported. Incomplete safe drafts can restore for further editing, while publishable export still requires full validation. Unknown versions are rejected without replacing current edits; preserve them for manual migration. Importing an exported draft or studio ZIP reproduces its catalog, route IDs and screenshot binaries.

The static studio has no repository-writing token and makes no automatic GitHub changes. Its visibility is not write protection: authorized repository commits control public content. Committed and Published states are verified in GitHub, not guessed by the client.

No video files, local recording paths, credentials, private correspondence or Discord message exports belong in this repository. Source URLs are public references, not footage copies. Retest dates, applicability and usefulness must reflect actual supplied observations.
